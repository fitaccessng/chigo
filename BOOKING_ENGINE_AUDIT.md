# Booking answer-persistence matrix

This matrix records the current server-side contract for the booking engine.
Question keys below are copied from the current schema definitions. `*` means
required when applicable, `?` means optional, and `if ...` records the schema
condition. The schema module remains authoritative if a key or rule changes.

| Service and stage | Customer fields | Server validation and persistence | Later read path and dependencies | Review and regression evidence |
| --- | --- | --- | --- | --- |
| All: location | `BookingLocationForm` fields, including addresses, locality, access, lift and coordinates | `booking_engine._location_payload`; `Booking` location columns and `workflow_data.location_access` | `location_places_for`, route/quote calculation, service-area validation | Quote review location summary; location and storage regression tests |
| All: property | `service_*` fields defined by `booking_questions_for(booking, 'property')` | `validate_question_answers`; `workflow_data.property.service_answers` via `save_workflow_section` | `validate_booking_question_data`, pricing and service-specific question rendering | Quote review detail summary; persistence reload tests |
| Move services: inventory | catalogue/custom selections and `inventory_*` fields | `replace_inventory`, `confirm_inventory`, `_store_inventory_answers`; `BookingInventory` plus `workflow_data.inventory_answers` | `inventory_requirements`, vehicle eligibility, quote calculation | Quote review inventory summary; inventory confirmation/idempotency tests |
| Residential/commercial: vehicle | `vehicle_type_id` | `save_vehicle_selection` revalidates eligibility; `workflow_data.vehicle` | `vehicle_options`, schedule and quote calculation | Quote review vehicle name; eligibility/tamper tests |
| Services | service selections and `addon_*` fields | `_validated_addon_answers`, `save_workflow_section`; `workflow_data.services` and `workflow_data.addon_answers` | duration and quote calculation; invalidation on material change | Quote review services; add-on persistence tests |
| Schedule | `move_date`, `preferred_time`, timing notes | date/time validation; `workflow_data.schedule` and `Booking.move_date`/`preferred_time` | availability and quote calculation | Quote review schedule; payment gating tests |
| Quote/payment | policy acknowledgement and provider session | `accept_quote`, `initialize_payment`, provider webhook verification | persisted quote lines, `calculation_data`, payment records | Quote breakdown and payment-stage workflow tests |

The complete service-specific schemas, conditional rules, and valid options are
in `moving_company/services/service_workflow.py`. `booking_stages_for`,
`next_booking_stage`, and `booking_stage_is_unlocked` are the authoritative
stage policy used by the booking route and progress UI.

### Persistence caveats

- Grouped property and inventory answer schemas are rendered from the booking's persisted workflow data on later requests. Conditional values are normalized server-side; changing an earlier section invokes downstream invalidation.
- `BookingEvent` confirmation idempotency is enforced by a unique key per booking confirmation generation. PostgreSQL row locking serializes concurrent confirmations; SQLite tests cover sequential retries and the uniqueness backstop, not true concurrent transaction scheduling.
- The quote review page displays persisted locations, property summary, inventory count, selected services and requested schedule. It does not yet render every answer in the schema; detailed answer-by-answer review remains a UX gap.
- Vehicle recommendation uses configured application vehicle capacities and booking load estimates. It is not proof of a vehicle being available; partner fleet and schedule availability require separate operational confirmation.
